Section 01

프로젝트 개요

가족 구성원이 사진과 글을 올리면 멀리 계신 할아버지가 슬라이드쇼 형태로 감상할 수 있는 PWA(Progressive Web App)입니다. 별도 앱 설치 없이 링크 하나로 모든 기기에서 동작하며, 홈 화면에 추가하면 일반 앱처럼 실행됩니다.

항목내용
앱 형태PWA (Progressive Web App)
서버 코드없음 — 100% 클라이언트 사이드
호스팅GitHub Pages (무료 정적 CDN)
데이터베이스Firebase Firestore (무료 Spark 플랜)
빌드 도구없음 — 순수 HTML/CSS/JS
월 운영비용0원 (무료 한도 내)
Section 02

파일 구조

전체 앱이 4개의 파일로 구성됩니다. React, Vue 등의 프레임워크를 사용하지 않아 빌드 과정 없이 브라우저가 직접 실행합니다.

memory-link-app/
├── index.html (40KB) 앱 전체 — HTML + CSS + JS 통합 단일 파일
├── manifest.json (569B) PWA 설치 정보 (앱 이름, 아이콘, 시작 URL)
├── sw.js (1.4KB) Service Worker — 오프라인 캐시 담당
└── icons/
    ├── icon-192.png Android 홈화면 아이콘
    ├── icon-512.png 스플래시 스크린용 아이콘
    └── icon.svg 원본 벡터 아이콘
파일역할크기
index.html앱의 모든 것 (UI 구조, 스타일, 로직)40KB
manifest.jsonPWA 메타데이터 — 브라우저가 읽어 설치 기능 제공569B
sw.jsService Worker — 별도 스레드에서 캐시 관리1.4KB

Section 04

화면 구조 (View 시스템)

별도 라우터 없이 CSS display 속성 토글로 화면을 전환합니다. 4개의 View가 항상 DOM에 존재하며, active 클래스가 있는 View만 표시됩니다.

view-landing (시작 화면) │ ├── "추억 올리기" ──▶ view-upload (사진·글 입력) │ │ │ └── "공유 설정" ──▶ view-setup (Firebase 연결) │ └── "할아버지 화면" ──▶ view-slideshow (슬라이드쇼 재생)
View ID역할주요 기능
view-landing시작 화면가족용 / 할아버지용 분기
view-upload업로드 화면사진 선택, 텍스트 입력, 클라우드 공유
view-slideshow슬라이드쇼자동 재생 (10초), 수동 이동, 진행 바
view-setup공유 설정Firebase 원탭 연결
Section 05

데이터 저장 구조 (3중 레이어)

데이터는 로컬 2단계 + 클라우드 1단계의 총 3중 구조로 관리됩니다.

사진 업로드 시 ↓ [1단계] IndexedDB (기기 로컬) — 사진(base64) + 텍스트 전체 저장 — 앱 재시작 시 자동 복원 ↓ 실패 시 (구형 브라우저) [2단계] LocalStorage (기기 로컬 백업) — 텍스트만 저장 (사진 제외, 5MB 한도) ↓ "슬라이드쇼 시작" 클릭 시 [3단계] Firebase Firestore (클라우드) — 사진 압축 후 base64로 저장 — 모든 가족 기기에 실시간 동기화

Firestore 데이터 구조

rooms (컬렉션)
  └── 할아버지 (문서 — 룸 코드)
        ├── lastActive: 1714123456789
        ├── agent: "Mozilla/5.0 ..."
        └── slides (서브컬렉션)
              ├── slide-0
              │     ├── order: 0
              │     ├── photo: "data:image/jpeg;base64,/9j/4AAQ..."
              │     ├── when:  "2024년 봄, 경주 여행"
              │     ├── who:   "할머니, 아빠(7살)"
              │     └── story: "그날 할아버지께서..."
              ├── slide-1 { ... }
              └── slide-2 { ... }
Section 06

사진 처리 파이프라인

Firebase Storage가 유료 플랜(Blaze)만 지원하도록 정책이 변경되어, Canvas API로 사진을 압축한 뒤 Firestore에 직접 저장하는 방식을 사용합니다.

[원본 사진 선택] 사용자가 파일 탐색기에서 선택 ↓ FileReader.readAsDataURL() [base64 문자열로 변환] 기기 메모리(IndexedDB)에 보관 ↓ "슬라이드쇼 시작" 클릭 → compressPhoto() 호출 [Canvas 리사이즈] — 긴 변 기준 최대 800px 축소 — canvas.toDataURL('image/jpeg', 0.70) ↓ [압축된 base64 → Firestore 저장]
원본압축 후압축률
iPhone 사진 (4MB)약 150~300KB약 93% 감소
일반 카메라 (8MB)약 200~400KB약 95% 감소
스크린샷 (500KB)약 50~100KB약 80% 감소
ℹ️
Firestore 문서 1개의 크기 한도는 1MB입니다. 압축 후 사진이 약 400KB 이하여야 안정적으로 저장됩니다. 매우 고해상도 사진(12MP 이상)은 압축률을 더 낮추거나 해상도 상한을 낮추는 조정이 필요할 수 있습니다.
Section 07

Firebase 실시간 동기화

업로드 흐름 (가족 → 클라우드)

슬라이드쇼 시작 버튼 클릭 → 기존 slides 서브컬렉션 전체 삭제 (batch.delete) → 사진 압축 (Promise.all) → 새 슬라이드 전체 재업로드 (col.doc('slide-N').set(...)) → Firestore가 변경 감지 → onSnapshot 콜백 실행 → 할아버지 화면 자동 갱신

수신 흐름 (클라우드 → 할아버지)

// Firebase 연결 시 1회 등록 — 이후 자동 실행
fbDb.collection('rooms').doc('할아버지')
  .collection('slides').orderBy('order')
  .onSnapshot(function(snapshot) {
    // 변경 발생 시 Firestore가 자동으로 이 콜백 실행
    // (폴링 없음 — WebSocket 기반 서버 push)
    slides = snapshot.docs.map(doc => doc.data());
    saveToStorage();   // 로컬에도 저장
    showToast('📲 가족이 추억을 업데이트했어요');
  });
✅
WebSocket 기반으로 동작하므로 주기적 새로고침 없이 실시간 수신됩니다. 가족이 사진을 올리면 할아버지 화면에 수 초 내에 반영됩니다.
Section 08

PWA 기술 상세

Service Worker (sw.js) — Cache First 전략

요청 발생 ↓ 캐시에 있음? → 캐시에서 즉시 반환 (오프라인도 가능) 캐시에 없음? → 네트워크 요청 → 성공 시 캐시에 저장 네트워크도 실패? → index.html 반환 (앱 껍데기라도 표시)

캐시 키는 'memory-link-v2'입니다. 앱 코드를 업데이트할 때 이 버전 번호를 올리면 구버전 캐시가 자동 삭제됩니다.

⚠️
Firestore 테스트 모드 만료일: 2026년 5월 25일
이 날짜 이후에는 데이터 읽기·쓰기가 전면 차단됩니다. 아래 보안 규칙으로 업데이트해야 합니다.

만료 전 적용할 Firestore 보안 규칙

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /rooms/{roomId}/{document=**} {
      allow read, write: if true;
    }
  }
}

적용 위치: Firebase Console → memory-link 프로젝트 → Firestore Database → 규칙 탭 → 게시
